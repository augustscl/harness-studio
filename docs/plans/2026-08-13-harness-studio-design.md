# Harness Studio 桌面客户端设计

## 目标

Harness Studio 是一个面向 macOS 的非官方 DeepSeek Harness 桌面客户端。用户双击应用后，客户端自动启动并监控本地 Harness Web 服务，在同一个原生窗口中提供会话、工作区、模型设置、工具审批和子智能体能力，不要求用户打开终端或手工管理端口与进程。

首版的成功标准是：应用可以从全新启动可靠进入 Harness 官方界面；退出应用时不遗留后台服务；服务启动失败时给出可理解、可恢复的反馈；能够生成可安装的 `.app` 与 `.dmg`；视觉上具有明确的 macOS 原生气质，而不是普通网页外包一层窗口。

## 产品形态

主窗口使用隐藏式 macOS 标题栏和内嵌交通灯按钮。顶部保留 52px 的客户端工具栏，显示产品标识、引擎健康状态，以及刷新、重启和日志入口。工具栏下方由 Electron `WebContentsView` 承载 Harness 官方 Web UI。这样既保留框架现有的完整能力与后续兼容性，又能由客户端负责原生窗口、生命周期和故障恢复。

启动期间显示独立的欢迎界面：深色石墨背景、柔和材质光晕、细颗粒纹理和克制的蓝青色状态光。启动分为“准备运行时”“启动 Harness”“连接界面”三个可感知阶段。若启动超过预期或进程退出，界面切换为错误卡片，提供重试、查看日志和打开数据目录，不暴露原始堆栈作为主要文案。

视觉语言遵循 macOS 的层级、材质和动效习惯：原生系统字体、半透明工具栏、1px 低对比边框、较大的内容留白、短距离弹性动效，并尊重 `prefers-reduced-motion`。不仿造系统设置页面，也不使用大面积营销渐变。

## 技术架构

应用使用 Electron、TypeScript 和 Vite。`@deepseek-ai/dsh` 固定到经过验证的 RC 版本，Electron 主进程通过独立子进程运行其 `dsh web` 入口。服务只监听 `127.0.0.1`，客户端先选择空闲高位端口，再轮询根页面完成健康检查。`DSH_HOME` 指向应用用户数据目录下的独立文件夹，日志写入应用日志目录；工作区仍由 Harness 官方 UI 管理。

主进程拥有全部高权限能力。渲染层关闭 Node integration、开启 context isolation，并只通过预加载脚本暴露窄 IPC：读取应用状态、重启引擎、重载 UI、打开日志和打开数据目录。Harness 页面运行在独立 `WebContentsView` 中，拒绝非用户触发的新窗口与权限请求，外部 HTTPS 链接交给系统浏览器。

引擎管理器采用显式状态机：`idle → starting → ready → stopping`，任何阶段都可以进入 `failed`。同一时刻只允许一个启动或停止操作。正常退出先发送 `SIGTERM`，等待有限时间后才强制终止。引擎输出写入轮转受控的文本日志和内存尾部，错误界面只展示末尾摘要。

## 错误处理与安全

端口冲突通过启动前探测和有限重试解决；超时、提前退出和 HTTP 不可达分别给出稳定错误码。应用不会将模型密钥复制到自身设置或日志中，密钥继续由 Harness 管理。默认遥测配置不由客户端改写，Web 服务不会绑定公网地址。外部导航、文件下载和系统权限均采用明确允许列表。

应用首版不承诺强于 Harness 本身的沙箱。README 会明确提醒：agent 仍是本机代码执行面，机密项目应放在容器、虚拟机或独立账号中运行。

## 验证

单元测试覆盖状态机、端口选择、日志裁剪和 URL 导航策略；进程测试使用可控的假服务验证启动、就绪、超时、崩溃与关闭。Electron 冒烟测试启动真实窗口，断言欢迎界面、工具栏和 Web 内容容器，并保存截图进行视觉检查。最终验证使用真实 `@deepseek-ai/dsh` 无密钥启动，确认首页响应、重启成功和应用退出后端口释放。打包后对 `.app` 做一次冷启动检查，再生成 arm64 `.dmg`。

## 首版边界

首版不重写 Harness 的会话列表、聊天渲染和模型设置，也不实现远程服务器、多窗口或自动更新。这些能力只有在桌面壳稳定、官方 API 形成版本承诺后再评估。
